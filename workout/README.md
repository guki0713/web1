# 운동일지 — 주간 운동량 관리 웹앱

Apple Numbers로 연도별·월별 수기 관리하던 운동일지를 대체한다.
근지구력·심폐지구력 훈련량의 객관적 자기평가(주간 운동량 관리)에 초점을 둔다.

## 쓰는 법

**`workout/index.html` 하나만 열면 된다.** 설치할 것도, 실행해 둘 프로그램도,
인터넷 연결도 필요 없다. 화면과 기능이 그 파일 안에 모두 들어 있어서
파일 자체가 곧 프로그램이다.

GitHub Pages를 켜면 `https://<사용자>.github.io/web1/workout/` 주소로 열리고,
휴대폰 브라우저의 "홈 화면에 추가"로 앱처럼 띄워 쓸 수 있다.

## 기록은 어디에 저장되나

브라우저 안(localStorage)에만 저장된다. 서버로 전송되지 않고, **저장소에도
커밋하지 않는다** — 이 저장소는 공개되어 있고 날짜별 훈련량은 개인 정보이기 때문이다.

그래서 기기마다 기록이 따로 논다. 옮길 때는 앱의 **데이터** 탭을 쓴다.

- **JSON 내보내기** — 백업 파일 생성. 주기적으로 받아 두면 기기 분실에 대비된다.
- **JSON 가져오기** — 새 기기에서 한 번 불러오면 기록이 채워진다.
  (날짜·종목·수량·세트 기준으로 중복은 자동 제외되므로 여러 번 넣어도 안전하다.)
- **CSV 내보내기** — 스프레드시트로 분석하고 싶을 때.

## 기존 Numbers 템플릿과의 대응

| Numbers 템플릿 | 웹앱 |
|---|---|
| 연도별 파일 × 12개 월 시트 수동 복사 | 하나의 앱, 날짜 기반 자동 분류 (월간 탭이 기존 표와 동일한 배치) |
| `푸시업 = G열+I열`, `하체 = H열+J열` 수식 유지보수 | 파생 열 자동 계산 (푸시업 합계 = 콤보상체 + 단독푸시업, 하체 합계 = 콤보하체 + 단독하체) |
| 셀 수식으로 세트 기록 (`=5×10+5×10`) | 입력창에 `5x10+5x10` 그대로 입력하면 자동 합산, 세트 내역도 보존 |
| 마지막 행 `SUM(...)` 월 합계 | 월간 합계 + **주간 합계·전주 대비·4주 평균·주간 목표** 자동 집계 |
| 연도 간 비교 어려움 | 추이 탭: 주간 운동량 차트, 연도별 비교표 |

## 종목 체계

원시 기록(직접 입력): 턱걸이, 푸시업 콤보(로우·해머컬), 단독푸시업,
하체 콤보(밀프·스쿼트·카프), 단독하체, 러닝(km), 복근.

파생 합계(자동): **푸시업 합계** = 푸시업(구기록) + 콤보상체 + 단독푸시업,
**하체 합계** = 하체(구기록) + 콤보하체 + 단독하체.
2023년 상반기의 통합 기록(푸시업/하체/중량스쿼트/딥스)은 구기록 종목으로 보존되며
합계에 자동 반영된다.

## 파일 구성

```
workout/
  index.html      ← 배포용 단일 파일 (빌드 결과물, 이걸 열면 된다)
  src/            ← 편집용 원본
    index.html  style.css  app.js  history.js
tools/
  convert_numbers.py    .numbers → JSON 변환
  build_single_file.py  src/ → index.html 빌드
```

`src/`를 고친 뒤에는 반드시 다시 빌드한다.

```bash
python3 tools/build_single_file.py
```

## Numbers 파일에서 기록 가져오기

```bash
pip install numbers-parser
python3 tools/convert_numbers.py 2026운동일지.numbers -o 백업.json
```

만들어진 `백업.json`을 앱의 **데이터 → JSON 가져오기**로 불러오면 된다.
연도별 헤더 변화(팔굽혀펴기/푸시업, 맨몸하체/하체 등)는 자동으로 정규화되고,
다른 셀을 참조하는 파생 수식과 합계 행은 건너뛴다.

**변환 결과 JSON은 커밋하지 않는다.** `.gitignore`가 막아 두었다.
