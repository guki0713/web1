## 1. 처음 여는 법

### 휴대폰 (권장)

1. 사파리로 `https://guki0713.github.io/web1/` 접속
2. 아래 공유 버튼(⬆️) → **홈 화면에 추가**
3. 홈 화면 아이콘으로 열면 주소창 없이 앱처럼 뜬다

한 번 연 뒤에는 **인터넷 없이도 열린다.** 앱이 기기에 저장되기 때문에
지하 헬스장이나 비행기 모드에서도 기록할 수 있다.

### 컴퓨터

같은 주소를 브라우저로 열면 된다. 또는 `workout/index.html` 파일 하나를
받아서 더블클릭해도 똑같이 동작한다 — 설치도, 인터넷도 필요 없다.

### 주의: 기록은 기기마다 따로 논다

폰에서 적은 기록은 폰에만, 컴퓨터에서 적은 기록은 컴퓨터에만 남는다.
서버에 올라가지 않기 때문이다. 옮기려면 [3장](#3-기록을-지키는-법)을 볼 것.

## 2. 화면 여섯 개

### 입력 — 오늘 한 운동 적기

날짜를 고르고 종목별로 숫자를 넣는다. 계산기를 두드릴 필요 없다.

```
반복 × 세트 × 사이클 = 총량
 10  ×  5   ×   2    =  100
```

- **반복** — 한 세트에 몇 번
- **세트** — 몇 세트 (비우면 1)
- **사이클** — 운동+휴식을 몇 번 돌았나 (비우면 1)
- **총량** — 자동 계산된다. 총량만 알면 여기에 바로 적어도 된다

러닝은 km 하나만 적는다.

적은 기록은 아래 목록에 `10×5×2 100회` 처럼 내역과 함께 남는다.
✕를 누르면 지워진다.

### 주간 — 이번 주 얼마나 했나

- **요약 카드** — 종목별 주간 합계, 전주 대비 증감, 4주 평균
- **주간 목표** — 목표를 적으면 달성률 막대가 뜬다. 비워 두면 최근 4주 평균의
  +5%를 회색으로 제안하고, 옆 버튼을 누르면 바로 적용된다
- **훈련 부하** — 이번 주가 평소보다 얼마나 급한지 ([4장](#4-지표-읽는-법))
- **요일별 상세** — 무슨 요일에 몰려 있는지

◀ ▶ 로 지난 주를 볼 수 있다.

### 월간 — 기존 Numbers 표와 같은 배치

날짜별 × 종목별 표. 월요일마다 굵은 선이 들어가 주 단위가 눈에 들어온다.
파란 숫자는 자동 합산된 열이고, 셀에 마우스를 올리면(PC) 세트 내역이 보인다.

### 테스트 — 좋아지고 있나 재기

주간 총량은 "얼마나 했는가"만 말해준다. 실력이 늘었는지는 **같은 조건에서
최대 몇 개를 하는가**로 재야 한다.

1. 종목과 BPM(기본 30 = 2초에 1회), 준비시간(기본 15초)을 고른다
2. **시작**을 누른다
3. 준비시간 동안 **째깍째깍** 소리가 난다 (작게)
4. 마지막 3초에 **삑 삑 삑** 크게 울린다
5. 시작음과 함께 영어로 one, two, three... 세어 준다
6. 박자를 놓치는 순간 **정지**를 누른다 → 그때까지 횟수가 기록된다

같은 BPM으로 재면 속도가 고정되므로 회차 간 비교가 공정해진다.
**월 1회 정도, 비슷한 시간대·컨디션에서** 재는 것을 권한다.

- **영어 음성 / 신호음** 선택 가능. 음성이 안 되는 기기에서는 자동 전환된다
- 소리 없이도 쓸 수 있게 카운트마다 숫자가 튕긴다
- 메트로놈 없이 잰 결과는 **직접 입력**으로 넣는다

### 추이 — 축을 바꿔가며 비교

|  | 종목 하나 | 전체 비교 |
|---|---|---|
| **주별** | 그 종목의 주간 변화 | 주별 종목 비중 |
| **월별** | 월간 변화 | 월별 비중 |
| **연별** | 연간 변화 | 연도별 비중 |

**전체 비교**는 누적 막대라 어떤 운동에 치우쳐 있는지 한눈에 보인다.
러닝(km)은 회 단위와 섞으면 의미 없는 숫자가 되므로 막대에는 넣지 않고
아래 표에서 본다.

**연간 히트맵** — 하루가 칸 하나. 색이 진할수록 그날 부하가 크다.
운동일수와 최장 연속일도 함께 나온다.

### 데이터 — 백업과 이전

내보내기 / 가져오기 / 전체 삭제. [3장](#3-기록을-지키는-법) 참고.

## 3. 기록을 지키는 법

### 기록이 어디에 있나

**브라우저 안에만** 있다 (localStorage). 서버로 전송되지 않고, 저장소에도
올라가지 않는다. 이 저장소는 공개되어 있고 날짜별 훈련량은 개인 정보이기 때문이다.

장점은 아무도 볼 수 없다는 것이고, 단점은 **잃어버리기 쉽다는 것**이다.
아래 상황에서 기록이 사라진다.

- 사파리 데이터·방문 기록 삭제
- 기기 초기화, 분실
- 홈 화면 앱을 지웠다 다시 추가

### 백업 (중요)

**데이터 탭 → JSON 내보내기.** 파일이 하나 받아진다. 이걸 iCloud Drive나
메일함 등 안전한 곳에 두면 된다. **한 달에 한 번** 정도를 권한다.

### 다른 기기로 옮기기

1. 원래 기기에서 **JSON 내보내기**
2. 파일을 새 기기로 옮긴다 (iCloud Drive, 메일, 에어드롭 등)
3. 새 기기에서 **JSON 가져오기**

날짜·종목·수량·세트가 같은 기록은 자동으로 걸러지므로, 여러 번 넣어도
중복되지 않는다. 두 기기에 각각 다른 기록이 있어도 서로 가져오면 합쳐진다.

### CSV 내보내기

엑셀·Numbers로 직접 분석하고 싶을 때 쓴다.

## 4. 지표 읽는 법

### 훈련 부하 (급성:만성 부하비)

```
이번 주 부하 ÷ 최근 4주 평균 부하
```

부하 = 총 반복수 + 러닝 km × 100. 종목이 다른 운동을 한 숫자로 합치기 위한
대략적인 환산이며, 생리학적 등가는 아니다. **절대값이 아니라 주별 변화율**을
보는 지표다.

| 값 | 판정 | 뜻 |
|---|---|---|
| 0.8 미만 | 훈련량 급감 | 이 상태가 이어지면 쌓아둔 체력이 준다 |
| 0.8 ~ 1.3 | **적정** | 무리 없이 늘려가는 구간 |
| 1.3 ~ 1.5 | 주의 | 증가가 빠르다. 다음 주는 유지하거나 조금 줄일 것 |
| 1.5 초과 | 과부하 위험 | 급격한 증가는 부상 위험을 높인다 |

스포츠과학에서 부상 위험 예측에 쓰는 지표를 그대로 가져왔다.

### 파생 합계

- **푸시업 합계** = 푸시업(구기록) + 콤보1 + 푸시업(단독)
- **하체 합계** = 하체(구기록) + 콤보2 + 맨몸스쿼트

콤보 운동은 여러 동작이 섞여 있어도 푸시업/하체 총량에 포함된다.
"구기록"은 2023년 상반기에 통합해서 적던 방식으로, 화면에는 안 보이지만
합계에는 반영된다.

### 표시 순서

어디서나 같다: 러닝 → 푸시업 → 턱걸이 → 복근 → 하체 → 콤보.
합계가 있는 종목은 합계를 먼저, 바로 뒤에 단독 카운트를 놓는다.

## 5. 문제가 생겼을 때

### 소리가 안 난다

1. 아이폰 **측면 무음 스위치**를 해제한다 (가장 흔한 원인)
2. 볼륨을 올리고 테스트 탭의 **[소리 확인]** 을 누른다
3. 진단 네 줄이 뜬다 — 소리 장치 상태, 무음 스위치 무시 여부, 음성 재생 가능
   여부, 실행 형태. 어디서 막혔는지 여기서 알 수 있다
4. 신호음은 나는데 영어 음성만 안 나오면 그 기기의 제약이다.
   선택창에서 **[신호음]** 을 고르면 된다

### 앱을 고쳤는데 폰에서 안 바뀐다

오프라인용으로 기기에 저장된 옛 버전이 뜨는 것이다. **새로고침을 두 번** 하면
새 버전이 잡힌다. 그래도 안 되면 사파리를 완전히 닫았다 다시 연다.

### 기록이 사라졌다

백업 JSON이 있으면 **데이터 → JSON 가져오기**로 복구한다.
백업이 없으면 복구할 수 없다. 그래서 3장이 중요하다.

### 화면이 이상하다

가로 스크롤이 생기거나 글자가 깨지면 새로고침. 계속되면
`workout/src/style.css` 를 확인한다.

## 6. 프로그램이 어떻게 만들어져 있나

### 파일 구성

```
workout/
  index.html            ← 배포용. 이 파일 하나가 앱 전체다 (빌드 결과물)
  sw.js                 ← 오프라인 지원 (기기에 앱을 저장)
  manifest.webmanifest  ← 홈 화면 앱 정보
  icon.svg              ← 아이콘
  src/                  ← 편집용 원본 (여기를 고친다)
    index.html            화면 뼈대와 탭
    style.css             색·배치
    app.js                모든 기능
    history.js            시드 기록 (비어 있음 — 개인 기록은 커밋하지 않는다)
tools/
  build_single_file.py  ← src/ 를 index.html 하나로 합친다
  convert_numbers.py    ← .numbers 파일을 JSON으로 바꾼다
```

**중요: `workout/index.html` 을 직접 고치지 말 것.** 빌드하면 덮어써진다.
항상 `workout/src/` 를 고치고 빌드한다.

### 왜 파일 하나로 합치나

설치할 것도, 서버도, 빌드 도구도 없이 파일 하나만 열면 동작하게 하기 위해서다.
GitHub Pages에서 주소도 짧아지고, 오프라인 저장도 간단해진다.

### app.js 구조

위에서부터 순서대로 읽으면 된다.

| 구역 | 하는 일 |
|---|---|
| 종목 정의 | `EXERCISES`, `DERIVED`, `METRIC_ORDER` — 종목과 표시 순서 |
| 저장소 | localStorage 읽기/쓰기, 옛 데이터 마이그레이션 |
| 날짜 유틸 | 주 시작은 월요일 |
| 집계 | 기간별 합계, 파생 합계 계산 |
| 훈련 부하 | 부하 환산과 ACWR |
| 뷰 라우팅 | 탭 전환, `el()` 로 화면 조립 |
| 소리 | `audio`(신호음), `speaker`(음성), `metronome`(박자) |
| 화면 6개 | `renderLog`, `renderWeek`, `renderMonth`, `renderTest`, `renderTrend`, `renderData` |

화면 그리기는 전부 `render()` → `views[현재탭]()` 한 갈래로 흐른다.
상태가 바뀌면 `saveState(); render();` 로 통째로 다시 그린다.
빠르고 단순해서 이 규모에서는 이 방식이 낫다.

### 데이터 모양

```js
{
  entries: [ { id, d: "2026-07-26", ex: "pullup", v: 100, s: "10×5×2" } ],
  tests:   [ { id, d: "2026-07-26", ex: "pullup", reps: 12, bpm: 30 } ],
  goals:   { pullup: 500, running: 20 }
}
```

`ex` 는 **저장용 내부 이름**이라 화면 표시 이름과 다르다.
표시 이름을 바꿔도 기존 기록이 유지되는 이유가 이것이다.

## 7. 고치고 늘리는 법

### 기본 절차

```bash
# 1. src/ 안의 파일을 고친다
# 2. 빌드
python3 tools/build_single_file.py
# 3. 확인 — 브라우저로 workout/index.html 을 연다
# 4. 커밋 & 푸시 → GitHub Pages가 1~2분 뒤 반영
```

빌드는 `sw.js` 의 캐시 이름도 자동으로 갱신한다. 이걸 잊으면 기기에 옛
버전이 계속 남으므로 **반드시 빌드하고 커밋**해야 한다.

### 종목 추가하기

`src/app.js` 맨 위 `EXERCISES` 에 한 줄을 넣고, `METRIC_ORDER` 에 원하는
위치를 잡아 준다. 그게 전부다 — 입력·주간·월간·추이가 알아서 따라온다.

```js
const EXERCISES = [
  ...
  { key: "plank", name: "플랭크", unit: "초" },
];

const METRIC_ORDER = [
  "running", "pushup_total", "solo_pushup", "pullup", "abs",
  "plank",              // ← 넣고 싶은 자리에
  "legs_total", "solo_legs", "combo_upper", "combo_lower",
];
```

`key` 는 한 번 정하면 바꾸지 말 것. 저장된 기록이 이 이름으로 남는다.
`decimal: true` 를 붙이면 러닝처럼 소수점 입력이 된다.

### 표시 순서만 바꾸기

`METRIC_ORDER` 배열 순서만 바꾸면 표·선택창·차트가 전부 따라온다.
입력 폼 순서는 `EXERCISES` 배열 순서를 따른다.

### 색 바꾸기

`src/style.css` 맨 위 색 토큰만 고치면 전체가 바뀐다.
라이트/다크 세 곳(`:root`, `prefers-color-scheme: dark`, `[data-theme="dark"]`)을
같이 고쳐야 한다.

### 화면(탭) 추가하기

1. `src/index.html` 의 `#tabs` 에 버튼 추가
   ```html
   <button data-view="mynew">새탭</button>
   ```
2. `src/app.js` 의 `views` 에 등록
   ```js
   const views = { ..., mynew: renderMyNew };
   ```
3. `renderMyNew()` 함수를 만들어 `app.append(...)` 로 내용을 넣는다

기존 `render*` 함수 하나를 열어 흉내 내는 편이 빠르다.

### 화면 조립 도구 `el()`

```js
el("div", { class: "card" },
   el("h2", null, "제목"),
   el("button", { class: "btn", onclick: () => alert("눌림") }, "누르기"))
```

`on...` 으로 시작하는 속성은 이벤트로 연결되고, 나머지는 그대로 붙는다.

### Numbers 파일에서 기록 가져오기

```bash
pip install numbers-parser
python3 tools/convert_numbers.py 2027운동일지.numbers -o 백업.json
```

만들어진 JSON을 앱의 **데이터 → JSON 가져오기**로 넣으면 된다.
연도별로 헤더 문구가 달라도(팔굽혀펴기/푸시업 등) 자동 정규화되고,
다른 셀을 참조하는 수식과 합계 행은 건너뛴다.

**변환 결과 JSON은 커밋하지 말 것.** `.gitignore` 가 막아 두었다.

### 소리를 건드릴 때 주의

iOS는 소리·음성 요청이 **사용자 조작과 같은 실행 흐름 안**에 있을 때만
허용한다. `await` 을 먼저 걸면 그 뒤의 요청은 무시된다.

```js
// 올바른 순서
const { ctx, ready } = audio.unlockSync();   // 기다리지 않는다
speaker.say("Get ready");                    // 조작 흐름 안에서 먼저
await ready;                                 // 기다리는 건 그 다음
```

실제로 이것 때문에 "기기가 음성을 지원하지 않는다"는 잘못된 판정이 났었다.

## 8. 앞으로 해볼 만한 것

지금은 넣지 않았지만 필요해지면 검토할 만한 것들.

**기기 간 자동 동기화** — 지금은 JSON을 손으로 옮긴다. Supabase 같은 서비스를
붙이면 로그인만으로 어느 기기에서든 이어서 쓸 수 있다. 다만 계정 화면이 생기고
기록이 외부 서버에 저장되며, "파일 하나로 끝나는" 지금의 단순함을 잃는다.
기기를 자주 옮겨 다니게 되면 그때 검토할 것.

**백업 알림** — 마지막 백업 후 30일이 지나면 데이터 탭에 표시를 띄우는 정도.
기록 유실을 막는 값싼 장치다.

**세트 사이 휴식 타이머** — 헬스장 편의 기능.

**부위별 균형 보기** — 상체/하체/코어 비중이 치우쳤는지.

**테스트와 총량의 상관** — 훈련량을 늘린 달에 실제로 최대반복이 늘었는지를
겹쳐 보는 그래프. 테스트 기록이 6회 이상 쌓이면 의미가 생긴다.

## 부록: 기술 메모

- 의존 라이브러리 없음. 표준 웹 기능만 사용한다
- 차트는 SVG를 직접 생성한다 (외부 차트 라이브러리 없음)
- 폰트는 기기 내장 글꼴을 쓴다. 한글 웹폰트는 수 MB라 헬스장 환경에 부적합
- 오프라인은 서비스 워커의 stale-while-revalidate 방식.
  캐시본을 먼저 띄우고 뒤에서 새 버전을 받아 둔다
- 테마는 CSS 변수 3벌(기본/OS 다크/강제 지정)로 처리한다
- 메트로놈 박자는 `AudioContext.currentTime` 기준. `setInterval` 은 화면이
  꺼지면 밀리지만 오디오 시계는 밀리지 않는다.
  측정값: 30 BPM에서 간격 2000 / 1999 / 2001 ms
